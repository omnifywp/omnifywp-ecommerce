Overview & Philosophy

1. Introduction to OmnifyWP

Discover how OmnifyWP eCommerce delivers ultra-high performance and a modern commerce experience on WordPress.

OmnifyWP eCommerce is an enterprise-grade, high-performance eCommerce solution engineered specifically for modern WordPress sites. By completely bypassing the legacy wp_posts and wp_postmeta bottleneck, OmnifyWP delivers sub-millisecond page loads, military-grade digital asset security, and high-converting checkouts.

Zero-Postmeta Latency

Product, order, customer, and inventory records live in 27 dedicated normalized relational SQL tables with optimized multi-column indexes, achieving sub-millisecond queries even with catalogs of millions of items.

Cryptographic Digital Locker

Deliver software, digital downloads, courses, and media securely with SHA-256 HMAC-signed URLs, time-based expiration, download caps, and automated file revocation upon refund.

Conversion-First Storefront

Modern responsive shop grid, sticky product cards, variant swatches, urgency badges, real-time cart scarcity timers, and frictionless single/multi-step checkouts designed to convert.

Architectural Comparison: OmnifyWP vs Legacy WooCommerce

Architecture Dimension Legacy WooCommerce OmnifyWP eCommerce
Database Storage Overloaded wp_posts & wp_postmeta EAV table joins 27 Dedicated Normalized SQL Tables (Clean Separation)
Query Execution Time 45ms – 250ms+ under large catalogs 0.4ms – 2.5ms indexed direct SQL queries
Digital Asset Delivery Basic PHP redirects or exposed download URLs HMAC-SHA256 Signed Tokens, 8KB chunk streaming
Refund Asset Security Manual access revocation required Instant Automatic File Revocation on order refund
Block Editor Integration Heavy legacy widgets & shortcode wrappers 100% Native Gutenberg Full Site Editing blocks
Built for Scale: Your blog posts, pages, and custom post types remain completely isolated from high-volume catalog queries. Backups, queries, and caching remain lightning fast as your store scales to millions in revenue.

Discount Types

  • Percentage Discount (%): Deducts a percentage from the eligible cart items (e.g. 20% off entire cart).
  • Fixed Cart Discount ($): Deducts a fixed currency amount from the order total (e.g. $15 off orders over $100).
  • Fixed Product Discount ($): Applies a fixed currency discount per individual eligible product unit.

Usage Restrictions & Rules

Fine-tune coupon eligibility to prevent discount abuse:

  • Minimum & Maximum Spend: Establish subtotal spend boundaries required to activate the promo.
  • Individual Use Only: Prevent shoppers from stacking promotional codes.
  • Usage Limit per Coupon: Cap the total times a coupon can be redeemed store-wide.
  • Usage Limit per User: Limit redemptions per customer email address (e.g. one-time use per customer).
  • Timezone-Aware Expiration: Expiration dates and times evaluate against your WordPress site timezone (using wp_timezone()), eliminating premature or delayed expiration.

Recovery Workflow

  1. Multi-Item Basket Capture: As soon as a customer enters their email address during checkout, Omnify serializes the entire shopping basket—including products, variations, quantities, and pricing.
  2. Threshold Evaluation: If no completed order occurs within 60 minutes, the session is flagged as Abandoned.
  3. Automated Reminder: Dispatches personalized recovery reminder emails containing direct, cryptographic 1-click checkout restoration links.
  4. Instant Session Restoration: Clicking the link reconstitutes the customer's entire basket with items, quantities, and active discounts intact.
  5. Conversion Attribution: Once purchased, the status transitions to Recovered, updating your recovery metrics.

1. Stripe Setup Guide (Credit/Debit, Apple Pay, Google Pay, SEPA)

Step 1: Log in to your Stripe Dashboard at stripe.com.

Step 2: Go to Developers → API keys. Copy your Publishable key (pk_live_... or pk_test_...) and Secret key (sk_live_... or sk_test_...).

Step 3: Go to Developers → Webhooks → Add endpoint. Set URL to https://yourdomain.com/wp-json/omnify/v1/webhook/stripe. Select events: payment_intent.succeeded, payment_intent.payment_failed, and charge.refunded. Copy the Signing secret (whsec_...).

Step 4: In WordPress, open Omnify → Settings → Payments → Stripe. Paste your Publishable Key, Secret Key, and Webhook Secret. Toggle Test Mode ON for sandbox testing, or OFF for live processing, and click Save Changes.

Step 5: Test transactions using Stripe's official card number 4242 4242 4242 4242, any future expiry date, and any 3-digit CVC.

2. PayPal Commerce Platform Setup Guide

Step 1: Visit developer.paypal.com and navigate to Dashboard → Apps & Credentials.

Step 2: Switch to Sandbox or Live, click Create App, select Merchant type, and copy your Client ID and Secret Key.

Step 3: Under App Webhooks, add https://yourdomain.com/wp-json/omnify/v1/webhook/paypal listening for CHECKOUT.ORDER.APPROVED, PAYMENT.CAPTURE.COMPLETED, and PAYMENT.CAPTURE.REFUNDED.

Step 4: In Omnify Settings → Payments → PayPal, paste Client ID and Secret, choose Sandbox or Live environment, enable Smart Buttons (PayPal, Pay in 4, Venmo, Cards), and save.

3. Razorpay Setup Guide (India: UPI, NetBanking, RuPay)

Step 1: Log in to your Razorpay Dashboard at dashboard.razorpay.com.

Step 2: Go to Account & Settings → API Keys. Click Generate Key to receive your Key ID and Key Secret.

Step 3: Go to Settings → Webhooks → Add New Webhook. Set URL to https://yourdomain.com/wp-json/omnify/v1/webhook/razorpay, enter a webhook secret passphrase, and select payment.captured, payment.failed, and refund.processed.

Step 4: In Omnify Settings → Payments → Razorpay, enter Key ID, Key Secret, and Webhook Secret, toggle Enable to ON, and save.

4. SSLCommerz Setup Guide (Bangladesh: bKash, Nagad, Rocket)

Step 1: Register a merchant account at sslcommerz.com. Obtain Sandbox credentials from integration support and production credentials from merchant.sslcommerz.com.

Step 2: Configure IPN (Instant Payment Notification) listener URL in SSLCommerz merchant panel: https://yourdomain.com/wp-json/omnify/v1/webhook/sslcommerz.

Step 3: In Omnify Settings → Payments → SSLCommerz, select Sandbox or Live environment, input your Store ID and Store Password, and save.

5. Cash on Delivery (COD) Setup Guide

Step 1: Open Omnify → Settings → Payments → Cash on Delivery and toggle Enable to ON.

Step 2: Configure Title, Description, and Customer Instructions for couriers.

Step 3: Restrict COD to physical items (virtual/downloadable items automatically hide COD). Set optional minimum and maximum order thresholds.

Step 4: Orders are initially assigned Processing or Pending Payment, transitioning to Completed when cash is received.

6. Direct Bank Wire Transfer (BACS) Setup Guide

Step 1: Open Omnify → Settings → Payments → Direct Bank Transfer and toggle Enable to ON.

Step 2: Add one or more business bank accounts: Account Name, Account Number, Bank Name, Sort Code/Routing Number, IBAN, and BIC/SWIFT.

Step 3: Orders are placed on On Hold status with account instructions displayed on screen and emailed to the buyer. Once the wire transfer clears in your bank, administrators mark the order as Processing or Completed.

8. Paystack Setup Guide (Africa: Nigeria, Ghana, Kenya, South Africa)

Step 1: Register at paystack.com and copy your Public Key (pk_live_...) and Secret Key (sk_live_...).

Step 2: Set Webhook URL to https://yourdomain.com/wp-json/omnify/v1/paystack/webhook.

Step 3: In Omnify Settings → Payments → Paystack, toggle Enable to ON, select Test or Live environment, paste keys, and save.

9. Tap Payments Setup Guide (Middle East & GCC)

Step 1: Register at tap.company and obtain your Public and Secret API keys.

Step 2: Point webhook destination to https://yourdomain.com/wp-json/omnify/v1/tap/webhook.

Step 3: In Omnify Settings → Payments → Tap Payments, paste your credentials and save.

10. Mollie Setup Guide (European Union: iDEAL, Bancontact, SEPA)

Step 1: Obtain your Live or Test API Key from mollie.com dashboard.

Step 2: In Omnify Settings → Payments → Mollie, enter your API Key and save. All localized European payment schemes are enabled automatically.

11. Khalti & eSewa Setup Guides (Nepal)

16. Variable Products, Preorders & Availability

Create variable products, configure the redesigned variation builder, and manage inventory, backorders, preorders, and the back-in-stock waitlist.

Variable products let you sell the same item in multiple configurations (size, color, format, license tier) with independent SKUs, pricing, and stock. OmnifyWP also models availability as a first-class concept: backorders, preorders, estimated delivery, and a customer back-in-stock waitlist.

Step 1 — Create a Variable Product

  1. Go to Omnify → Products → + Add New Product and set the Product Type to Variable.
  2. Open the Attributes panel and add the axes you sell on (e.g. SIZE, COLOR).
  3. Generate the variation matrix — each row inherits the parent pricing until overridden.

Step 2 — Configure Each Variation

  • Unified Attribute Badges: each axis uses a clean badge chip paired with an integrated dropdown and custom chevron.
  • Pricing & Stock Grid: SKU, Regular Price, and Sale Price share a normalized 42px/8px-radius layout with currency prefixes and an aligned Inventory Tracking toggle.
  • Media Actions: 32×32px icon buttons (upload / trash) with tooltips select and remove variation images.
  • Variation Notes: lightweight native textareas replace heavy WYSIWYG toolbars.

Step 3 — Availability, Backorders & Preorders

Open the Availability & Preorders panel on the variation:

  • Allow Backorders: permit purchases once stock reaches zero.
  • Preorder: enable preorders with a Release Date, a Preorder Limit, and a shopper-facing Notice Message.
  • Estimated Delivery: a full-width input with a transport icon prefix communicates per-variation dispatch expectations.

Back-In-Stock Waitlist

Out-of-stock products and variations display a customer opt-in. When stock is replenished, the automated Back-In-Stock Alert email fires to every waitlisted shopper.

Tip: Preorder and backorder flags are stored per product and per variation, so a single storefront can sell in-stock, backorderable, and preorder items side by side.

Help & Support

23. FAQ & Troubleshooting

Frequently asked questions, common troubleshooting scenarios, and performance tips.

Q: How does OmnifyWP achieve sub-millisecond database queries?

OmnifyWP stores products, variations, orders, and customer data in 27 dedicated normalized SQL tables (wp_omnify_*) with explicit multi-column indexes, bypassing WordPress's shared wp_posts and wp_postmeta tables completely.

Q: How do digital download links prevent unauthorized file sharing?

Download links use time-limited HMAC-SHA256 signatures salted with your WordPress secret keys. Actual server file paths are never exposed, and downloads are served via memory-safe 8KB chunk streaming with download attempt limits.

Q: How do I test Stripe payments without charging real credit cards?

Navigate to Omnify → Settings → Payments, toggle Test Mode on, enter your Stripe Test Publishable and Secret Keys, and use Stripe's standard test card numbers (e.g. 4242 4242 4242 4242).

Q: What happens to customer download access when an order is refunded?

When an order is refunded in Omnify → Orders, OmnifyWP immediately revokes all associated download tokens, preventing future file access.

Q: Can OmnifyWP run alongside standard WordPress block themes?

Yes! OmnifyWP is 100% Full Site Editing (FSE) ready and includes native Gutenberg blocks, patterns, and templates. It works seamlessly with block themes, classic themes, and headless frontends (Next.js, Nuxt).

Q: Where can I get support or report an issue?

Visit the official website at omnifywp.com or our plugin page on wp.org.
